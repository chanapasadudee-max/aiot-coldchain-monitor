    บทที่ 9: สคริปต์คลิปนำเสนอ AI Flow (Video Submission Script)¶

    บทพูดและแนวทางการบันทึกคลิปวิดีโอส่งงานตามข้อกำหนด: "clip อธิบาย flow ในการสั่งและตรวจงานกับ AI" (ความยาวแนะนำ: 4–5 นาที)

    โครงสร้างคลิปวิดีโอ (Video Storyboard)¶

    ช่วงเวลา หัวข้อ สิ่งที่ต้องโชว์บนหน้าจอ
    0:00 - 0:45 แนะนำตัว & ภาพรวม GitHub Pages หน้าเว็บ GitHub Pages + ลิงก์ Live MQTT Sandbox
    0:45 - 1:50 Flow การสั่งงาน AI (/grill-me + /plan) แชตที่ AI สัมภาษณ์วางแผน + Implementation Plan Artifact
    1:50 - 3:00 Flow การตรวจงานและทดสอบอัตโนมัติ (QA) รัน test_ai_and_api.py, test_e2e_playwright.py และ Serial Monitor ของ COM6
    3:00 - 4:30 สาธิตระบบจริง (Live Hardware + AI Guardrails) บอร์ด Cucumber RIS ส่งค่า HTS221/BMP280/MPU6050 -> แชตสั่งเปลี่ยนไฟ RGB -> ทดสอบ Guardrail บล็อกคำสั่งปิดไฟขณะ Critical
    4:30 - 5:00 สรุปผลลัพธ์ & ความคุ้มค่าทางธุรกิจ สรุป GMP CSV Export, B2B SaaS ROI และปิดท้าย

    บทพูดตัวอย่าง (Script Template)¶

    1. แนะนำตัว & โจทย์ (0:00 - 0:45)¶

    "สวัสดีค่ะ ดิฉันชื่อ นางสาว ชนาภา สดุดี รหัส 6610680214 วันนี้ขอเสนอโปรเจกต์วิชา CN466 เรื่อง AIoT Industrial Cold Chain & Sensitive Facility Monitor ค่ะ
    เราเลือกกลุ่มเป้าหมายเป็น วิศวกรโรงงานและนักศึกษา เพื่อสอนสร้างระบบเฝ้าระวังตู้แช่ยา/วัคซีน และห้อง Server โดยใช้บอร์ด Cucumber RIS จริงร่วมกับ AI แบบ 3 ชั้นค่ะ"

    2. Flow การสั่งงาน AI แบบมืออาชีพ (0:45 - 1:50)¶

    "ในขั้นตอนการพัฒนา เราไม่ได้สั่งให้ AI เขียนโค้ดสุ่มสี่สุ่มห้า แต่ใช้ Workflow แบบ /grill-me และ /plan:
    1. ให้ AI สแกนพอร์ต COM6 และตรวจเครื่องก่อน ทำให้พบว่าบอร์ด Cucumber RIS ของเรามีเซ็นเซอร์ I2C ครบ 3 ตัวคือ HTS221, BMP280 และ MPU6050 แถมมีไฟ NeoPixel RGB LED และในเครื่องมี Ollama qwen2.5 ติดตั้งอยู่แล้ว
    2. AI ถามคำถามทีละประเด็นเพื่อวางแผนร่วมกันจนได้เอกสาร Implementation Plan แล้วเราตรวจอนุมัติก่อนเริ่มเขียนโค้ดจริงค่ะ"

    3. Flow การตรวจงานและ Verification กับ AI (1:50 - 3:00)¶

    "หลัง AI เขียนโค้ดและแฟลชเฟิร์มแวร์ PlatformIO ลงบอร์ด COM6 เราตรวจงานด้วย 3 ด่าน:
    - ด่านฮาร์ดแวร์: ตรวจ Serial Monitor ยืนยันว่าเจอ I2C ครบ 3 ชิป (0x5F, 0x68, 0x76) และแยกไฟล์รหัสผ่าน Wi-Fi ไว้ใน secrets.h ไม่ให้หลุดขึ้น GitHub
    - ด่าน Automated Unit & API Test: รัน test_ai_and_api.py ตรวจสูตร Slope, Z-Score, Shock Detection และ Safety Guardrails
    - ด่าน E2E UI Test: รัน Playwright เปิดเบราว์เซอร์จริงตรวจ Dashboard และแคปภาพยืนยันผลค่ะ"

    4. สาธิตระบบทำงานจริง (3:00 - 4:30)¶

    (เปิดหน้า Dashboard + กล้องส่องบอร์ด Cucumber RIS)
    "ตรงนี้คือค่าสดจากบอร์ดจริงค่ะ สังเกตว่ามีครบทั้ง Temp, Humid, Pressure และ Vibration จาก MPU6050
    ทีนี้ลองกดจำลอง คอมเพรสเซอร์ดับ ระบบจะเปลี่ยนเป็นสีแดง CRITICAL และส่งคำสั่ง MQTT ไปสั่งไฟ RGB LED บนบอร์ดให้กระพริบสีแดงทันที!
    และลองทดสอบ AI Safety Guardrail โดยพิมพ์ในช่องแชตว่า 'ปิดไฟ' — ระบบจะขึ้น GUARDRAIL BLOCKED ห้ามปิดไฟเตือนขณะวิกฤต จนกว่าเราจะระบุ 'บังคับปิดไฟ' พร้อมลงบันทึกใน Audit Log ค่ะ"

    5. ปิดท้าย (4:30 - 5:00)¶

    "ทั้งหมดนี้ Deploy ขึ้น GitHub Pages เรียบร้อยพร้อมหน้า Live MQTT Sandbox ให้อาจารย์และผู้เรียนทดลองเล่นสดผ่านเบราว์เซอร์ได้ทันที ขอบคุณค่ะ"
